MCP Hangar has been installed.

NOTE: the 1.5 server refuses to bind HTTP on a non-loopback interface unless
EITHER a configured `auth:` block (see values.yaml `auth`) OR
`config.unsafeNoAuth=true` (demo/insecure only) is set. With both left at
their secure defaults, the pod will not become Ready.

{{- if gt (int .Values.replicaCount) 1 }}
{{- if eq (.Values.service.sessionAffinity | default "None") "ClientIP" }}

NOTE: service.sessionAffinity is ClientIP. From {{ .Chart.AppVersion }} the gateway serves
the MCP transport without a session, so replicas are interchangeable and the pin
is no longer needed. It is not harmful -- but it keys on the source address as
the Service sees it, so behind a proxy that does not preserve the client address
it sends everything to one pod. Set it to None unless you are pinning image.tag
to a gateway older than 2.7.0.
{{- else if .Values.image.tag }}

CHECK: image.tag is set to "{{ .Values.image.tag }}" and service.sessionAffinity is None.
If that tag names a gateway older than 2.7.0, its MCP sessions live in one
replica's memory and a round-robin Service will answer "Session not found" to
most requests -- set service.sessionAffinity to ClientIP, and pin your ingress
too. From 2.7.0 there is no session and None is correct. The chart cannot read
the version out of a tag, so it asks.
{{- end }}
{{- end }}

Get the application URL:

  kubectl port-forward --namespace {{ .Release.Namespace }} svc/{{ include "mcp-hangar.fullname" . }} 8080:{{ .Values.service.port }}

Check health:

  curl http://127.0.0.1:8080/health

View logs:

  kubectl logs --namespace {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }} -f
